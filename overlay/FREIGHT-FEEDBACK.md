# 货运提交与结果反馈调查 · 0.2.11

## 结论与证据

目前可以确认的是反馈模型缺口，不能确认原版不弹窗的唯一原因。

- 本机 `client_2026_11_03_log.txt` 的 19:09:44 请求只有 `queued`、`submitted`，19:09:51 停止跟踪，之后没有对应的新任务记录。旧 `submitted` 由本项目在函数返回后写入，不是服务端回执。
- 同日 16:47:53 的另一请求旁出现原版 `Verifying ownership of downloadable content on the remote trailer failed.`，随后又观察到任务变化。这说明必须分别记录原版条件与任务变化，不能把同时间出现的任务直接归因于请求；也不能用这条 DLC 提示解释 19:09 的另一请求。
- 11 月 4 日三段 0.2.10 / TMP 0.7.9.6 日志显示适配定位完成，没有新的 `freight/request` 记录，因此不是无提示问题的新复现。
- 当前复制链为 `Queue → Execute → SubmitCopy → request → UI event`。已留存的 0.7.9.4 静态反汇编中，UI event 在查找 UI 对象失败、或事件接收对象为空时允许直接返回。当前适配只检查上层上下文，无法证明这些更深条件成立。
- 自选链为 `QueueEditor → Execute → Edit → Generate`。生成函数也是无响应合同的调用；只有函数返回，不能据此得知货单已经生成。

以上原版分支依据本机留存的历史反汇编；没有对当前进程观测分支命中，也没有将未知新版本视为已经完成该逻辑的复核。没有引入新的 hook、调用入口或自动重试。

## 0.2.11 的改动

| 阶段 | 证据 | 界面含义 |
| --- | --- | --- |
| 排队 | 本地草稿/目标已记录 | 尚未调用 |
| 前置检查拒绝 | 输入、会话、任务或原生对象条件不成立 | 调用前检查未通过 |
| 调用已返回 | 请求/原版事件函数或生成函数返回 | 结果待核对，不保证服务端接收或弹窗出现 |
| 观察到任务 | 同一遥测代次中出现新的任务配置 | 待核对来源 |
| 用户确认 | 用户核对当前任务或原版货单 | 分别记录接取确认与货单确认 |
| 15 秒未观察到任务 | 已调用，尚未看到可关联变化 | 提示核对，不重发 |
| 两分钟未确认 | 本地观察超时 | 结果未知，不表示拒绝、取消或请求失效 |

主面板隐藏后保留右上角只读反馈，显示阶段、等待时间和返回快捷键，不请求鼠标或键盘锁。用户重新打开面板后提示收起；再次手动隐藏不会强制重新打开。

请求日志增加 `native_stage`、异常码、输入释放状态、会话代次、基线/观察/当前遥测修订及新鲜度。`copy.ui-event.returned` 只证明两次调用返回，不证明事件有接收者；`generate.returned` 也不是货单回执。`server_ack=unavailable` 明确表示缺少回执接口。原生异常保留最后到达的调用边界，并锁定到重启。

不读取聊天、不自动尾随其他日志，不把其他插件或原版日志行当作请求的机器可读结果。遥测缺失与有效“无任务”分别报告。现有人工核对、未知记录结束、冷却和会话失效规则保留。
