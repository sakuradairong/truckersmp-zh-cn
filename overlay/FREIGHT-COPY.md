# 0.2.11 自选做货与任务复制

本版保留现有货运接入，增加调用阶段诊断和主面板隐藏后的只读反馈，详见 [提交与反馈调查](FREIGHT-FEEDBACK.md)。

本地货运构建提供自选货运生成、普通任务复制和复制其他玩家的 World of Trucks 任务。WoT 操作不用于任意自选路线创建在线合同。

## 自选做货

1. 连接服务器，停稳车辆并处理完当前任务。右键进入本面板操作模式，打开货运 → 自选做货。
2. 点击“载入 / 重置原版选项”。这会同步原版调度器的草稿；不要同时在另一面板编辑同一货单。
3. 选择起点城市/公司、终点城市/公司、货物、挂车和紧急程度。每个列表支持搜索；弹窗与输入框等宽，选项独立滚动，长名称悬停查看，搜索栏显示匹配数量。原版空列表与搜索无匹配分别提示；重新打开时清空旧筛选。选项来自当前原版控件，不使用独立静态货物表。
4. 兼容公司货物、自有挂车和国家规则筛选会重载选项，需重新核对路线。每次改变都触发原版选择处理并读回；上次选择失效时不会强行沿用。
5. 在货场且原版允许时勾选“到场立即接取”，点击“生成并接取”。也可以选择生成后导航，或只生成货单。
6. 调用后主面板隐藏并释放输入，右上角保留只读反馈；若出现原版提示，处理后用显示快捷键返回。新的任务出现时核对货物、路线；仅生成货单的请求可以在原版查到货单后手动确认。

“已生成货单”与“已接取任务”分开。只看到旧任务、相同货物名或请求函数返回，都不会自动报告成功。SCS 遥测没有原版请求关联 ID，结果确认仍明确记录为用户核对。

## 普通 / WoT 任务复制

在“附近”选中玩家，点击“任务复制”，选择普通任务或 WoT 任务。WoT 复制要求原版在线能力处于可用状态；请求仍服从目标分享隐私、在线合同规则、挂车和 DLC 检查。调用返回不表示原版窗口已显示或服务端收到请求；若出现原版窗口，处理后回到本面板核对结果。

WoT 请求使用独立操作标记。确认新任务时，遥测市场必须为 external_contracts 或 external_market；普通市场任务不会被记录成 WoT 复制完成。

## 防止重复和错选

- 同一时刻只允许一个执行请求；两个模式共用等待、超时与会话失效处理。
- 提交前重新检查玩家 ID 与账号，或重新读取完整的原版草稿、列表成员、选中项身份和接取资格。过期草稿不会覆盖新会话。
- 界面动作排队至本帧结束再执行。生成和复制先释放输入；普通选项同步保留本面板操作模式。
- 停车、任务状态和线程检查必须通过；不在工作线程调用内部函数，不改写原版禁用标志。
- 两分钟未确认结果时标记未知，不自动重试。“停止等待”不撤销已发送请求，也不会把没有提示当成原版已取消。
- 停止或超时后仍观察现有遥测；若运输任务迟到，提供核对入口，不自动归因于本次请求。任务未经确认就结束时仍需核对，不把一次任务变化当作旧请求已完成。
- 从提交起至少等待两分钟，在同一会话、车辆停稳、遥测完整且当前没有任务时，可以手动点击“已核对，结束此记录”。先在原版确认没有待处理提示；此操作仅关闭本地未知记录，不取消服务端请求、不标记成功、不自动发送。随后有 15 秒冷却，并清空玩家选择和本地草稿，需重新选择或载入。
- 两分钟不是服务端请求的失效期限，结束本地记录也不证明原版操作已撤销。原生异常不提供手动解除，仍需重启；遥测会话重建需要重新连接服务器。断线、切服使旧草稿和待执行动作失效。

## 构建与更新兼容

默认构建不包含内部货运执行。可选本地构建：

```powershell
.\overlay\build.ps1 -NativeFreightCore '<已审查并留存的 0.7.9.4 基准 core_ets2mp.dll 路径>'
.\overlay\package.ps1
```

本地包名为 TruckCompanionOverlay-0.2.11-local-freight-windows-x64.zip。安装脚本默认备份替换；必须先退出游戏，保留第三方插件和已有配置。

当前仅支持 ETS2。0.7.9.4 是描述的审查基准，不是运行时版本白名单；包元数据使用 referenceClientTag 和 compatibilityPolicy 明确区分。构建描述仅从已审查的基准文件生成，客户端升级后仍使用留存的基准，不从未知新版自动学习规则；运行时版本字符串为空或变动不阻止结构定位。不加载目标 DLL，不计算 SHA/校验和。生成描述保存在 Git 忽略的 build/companion-overlay/native-freight/；没有把第三方面板、授权缓存或完整 TMP 文件加入源码。

描述仅屏蔽明确列出的相对地址操作数，保留寄存器、栈大小、字段偏移、虚表槽和分支形状；运行时要求指令形状与引用契约共同匹配后入口唯一，检查引用的代码/只读/可写区以及事件、控件名称。外形相同但类型名不同的函数不视为同一个候选；仍有多个完整匹配时停用。额外核对管理器构造器与复制入口指向同一全局对象、管理器虚表的请求槽、普通/WoT 选择入口、回调链及自选重置调用。控件禁用/选中状态的短 getter 在实际虚表槽处检查，允许编译器合并相同函数。对象和选择状态在执行前再次核对。

版本号、模块加载基址或函数/数据地址移动，不再单独触发停用。形状及引用关系一致时自动重新定位；不按固定差值推算地址，不回退到旧 RVA，不联网拉取偏移表。公共入口不匹配时停止货运；只有自选或 WoT 的专用检查失败时，普通复制仍保留。字段、控件语义或调用约定变动仍需重新审查；这些局部契约无法证明任意后续版本的全部行为，也不保证永久兼容。

一次联机会话内只在模块就绪后解析一次，失败不逐帧重扫；断线/切服清空地址和能力状态，原生异常锁定到重启。模块尚未加载时保持等待，不提前锁定失败。日志 freight/compat 记录基准、实际客户端版本、失败入口与各能力状态；不会记录聊天或新增账号信息。列表读取只在自选页操作时按间隔执行，并限制数量和字符串长度。

本次通过读取本机 0.7.9.5 文件，观察到原有 17 个入口的指令特征仍唯一存在但地址变化；这解释了 0.2.7 的版本号误拦截。没有执行目标模块或游戏内请求，静态定位不等于货运功能实机通过。

0.2.9 修正选项类型判断：原版 queryType 比较的是内部类型标识的指针，不能传入本 DLL 中字面相同的 Button:MenuItem 字符串。现在从已审查类型转换函数的相对引用解析原版标识，核对其文字及与选择函数的类型引用关系，再传入该原版地址；它继续随小更新重新定位。原生列表非空却无法识别任何选项时，读取失败，不再返回一个看似成功的空列表。

0.2.10 增加上述未知请求的手动结束流程，并保留 0.2.9 全部修复。本机旧版日志只有一次提交和停止跟踪，没有对应的新任务或接取结果；用户报告原版未弹提示。该证据能说明旧版永久锁定的触发路径，不能确定原版无提示的原因，也不能证明服务端已拒绝或取消请求。

## 交付边界

此版本使用私有原生调用，不是公开 SDK 提供的货运扩展，尚未取得 TMP 对本项目的明确接入许可。没有发布 Release，也没有联系官方或第三方面板作者。

本轮范围限于源码检查、历史材料阅读、编译和打包；未部署到实际游戏目录。遵从用户约束，不执行测试、烟测、SHA 校验或游戏内自动操作。编译成功不等于原版控件联动、WoT 服务端响应或现场接货已经实机验收。
