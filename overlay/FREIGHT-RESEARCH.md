# 自选货运与到货场接取：接口调查及实施路线

调查日期：2026-11-03。对应面板：Truck Companion Overlay 0.2.1。

最新接入判断见 [公开接入途径与接口要求](FREIGHT-INTEGRATION-OPTIONS.md)：官方知识库现已读到，不读档、自有挂车、邀请命令及接取距离的证据边界有进一步说明。本文的访问失败和未确认事项记录的是首轮调查状态。

后续深入调查见 [货运功能面板深入研究](FREIGHT-DEEP-DIVE.md)：补充 Trucky 的读档流程、TS-SE-Tool 的存档写入、单机原生生成/接取实现、目录与货场识别，以及适合本仓库的开发分期。本文保留为 0.2.1 首轮调查记录；“公开 SDK 不支持”不等于任何技术路线都无法实现。

## 用户目标与本次交付

目标是选择起点城市/公司、终点城市/公司、货物，生成任务；车辆到货场后，可以直接接取。仅显示运输统计或生成后重新读档，不算满足“现场直接接取”。

本次完成 TMP TAB 风格的自绘界面，以及独立货运页，展示遥测实际提供的当前货物、起终点城市、导航剩余距离。生成与接取仍为研究项，没有安装相关存档写入或内存写入实现，也没有放置可点击但不工作的生成/接取按钮。

## 已确认的证据

| 来源 | 确认内容 | 对本项目的影响 |
| --- | --- | --- |
| 用户提供的 TMP 原版界面截图 | 原版货运调度器有起终点城市/公司、货物、挂车、紧急程度、“立即接取任务”和“生成货运任务” | 原版已经具备相关用户流程；截图不能证明第三方 DLL 可调用它 |
| [SDK 架构](https://docs.truckersmp.com/client-sdk/concepts/architecture) | 按模块获取功能，返回 optional/Result；缺失功能应降级。游戏任务/经济读取属于 SCS 遥测范围 | 不因方法不可用而扫描私有地址或强行调用旧函数 |
| [Gameplay](https://docs.truckersmp.com/client-sdk/modules/gameplay) | 公开的是已挂载 TMP 包和无碰撞区事件 | 没有货运生成/接取或货场实体查询接口；车库、维修站、公司都可能是无碰撞区 |
| [User Interface](https://docs.truckersmp.com/client-sdk/modules/user-interface) | 公开操作为通知 ShowNotification | 未发现打开、填充或操作原版调度器的公开方法 |
| [Intents](https://docs.truckersmp.com/client-sdk/advanced/intents) | 列出公开 Bus 和需要项目申请的 Chat | 公交任务模块不是卡车货运模块；Chat 也不能据此推定有货运命令 |
| [SDK 最新发布](https://github.com/TruckersMP/GameClientSDK/releases/tag/v1.1.0) | GitHub latest API 返回 v1.1.0，发布于 2026-08-28，新增车辆/挂车包围盒读取 | 本次查询没有发现已发布的货运生成或接取 API |
| 本地 `vendor/tmp-sdk/include/TruckersMP` | 搜索货运/接取/公司相关符号，仅发现 VTC 及 Bus 相关接口，没有卡车货运创建/接受接口 | 与本次公开文档调查一致 |
| 本地 SCS `common/scssdk_telemetry_common_configs.h` | job 配置可读货物、起终点城市和公司、市场、装载状态等；空属性表示没有任务 | 可扩展当前任务展示，但不提供公司货单列表、生成和接取操作 |

本次多次访问 TruckersMP 知识库发生超时或连接断开，因此**没有核实**“立即接取”在当前客户端对货场距离、自有挂车、已有任务、DLC、服务器等条件的精确规则；不能编造距离阈值或保证任意货场都能接。需要以原版调度器的当场提示为准。已读到的 SDK 文档并不承诺未来一定增加货运接口。

## 可选路线

| 路线 | 自选货运 | 到场直接接取 | 更新兼容性与结论 |
| --- | --- | --- | --- |
| 由玩家使用 TMP 原版货运调度器 | 原版已有 | 原版界面有立即接取选项，具体条件待核实 | 当前可用流程；0.2.1 继续显示任务信息，不代点原版控件 |
| 本面板通过正式货运 API | 尚无已确认公开接口 | 尚无已确认公开接口 | 能完整承接目标的优先路线，前提是获得正式接口/扩展包及其文档 |
| 本面板生成一份新存档 | 需另行实现货单、公司和挂车结构编辑 | 必须读档，不是当前会话直接接取 | 可作为独立离线工具研究，不能声称满足本次现场接取目标 |
| 固定地址、特征扫描、私有函数调用、原版控件定位/自动点击 | 可能依赖逆向或布局细节 | 成功及条件均未验证 | 与减少更新失效的方向冲突，本方案不采用 |

## 正式接口可用时的开发设计

1. **先确认接口合同。** 需要可枚举的城市/公司/货物及稳定 ID、挂车/DLC 限制、当前货场标识、可接取状态与失败原因、生成任务返回的唯一 ID、接取结果以及任务生命周期事件。不能把 NCZ 当成货场，不能把一次按钮调用成功当成任务已接受。
2. **独立货运适配层。** 提供能力状态、目录读取、当前位置、草稿检查、生成、接取、任务状态读取。能力缺失时只显示当前任务；SDK 不兼容或服务器拒绝时明确显示原因。不记录私有函数地址。
3. **草稿与运行状态分开。** 草稿记录起终点城市/公司 ID、货物 ID、货单市场、挂车与紧急程度；显示名仅用于界面。目录按游戏版本、DLC、地图/已挂载内容分组，版本改变后重新确认，不跨版本套用旧 ID。
4. **生成流程。** 选定目录项 → 确认草稿可用 → 玩家点击生成 → 防止重复请求 → 等待正式结果和任务 ID。掉线或超时时先查询是否已经生成，不能盲目重试造成重复货单。
5. **现场接取流程。** 用正式公司标识确认到达起点货场，要求当前会话、位置和可接取状态新鲜有效；停车、挂车及现有任务冲突按正式接口规则处理。显示明确的“接取此任务”，由用户点击，等待任务状态确认；离场、切档、掉线立即作废旧的可接取状态。
6. **接取后展示。** 用 SCS 的任务配置与正式货运结果更新货物、公司、路线；不把离线旧缓存冒充当前任务。保留现有驾驶/编辑切换，避免误占驾驶输入。
7. **接口确认后的第一期范围。** 先支持 ETS2 标准货运市场、单个任务、单次生成与接取；自有挂车、特殊运输、World of Trucks、ProMods/自定义地图分别依正式接口支持扩展，不默认混用。

待向官方核实的问题已整理如下，但**未发送询问**：是否有已发布/可申请的货运扩展；能否枚举公司货单并生成；能否获取公司到场状态和接取资格；是否提供接取操作与结果；各游戏/市场/地图的支持范围；是否有正式调度器入口或文档化命令。

## 离线方案的独立边界

若以后选择存档生成路线，应明确选定游戏、档案和源槽，只复制到新槽；解析格式、公司引用、挂车与任务关联后只编辑副本，保留源存档。发布前必须有相应的结构校验和用户允许的验收阶段。离线文件生成和游戏成功加载是两项独立结果，且仍需读档。本次禁止测试、烟测、SHA 校验，因此没有执行该路线，也没有读取或修改玩家真实存档。
